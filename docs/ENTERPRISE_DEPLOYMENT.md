# הפעלת מערכת OCR ארגונית

התצורה מפעילה PostgreSQL, API, שני עובדי OCR, תחזוקה, Next.js, HTTPS וניטור. היא מיועדת לשרת Linux יחיד עם Docker Compose v2. קריסת השרת כולו גורמת להשבתה עד להתאוששותו. אין כאן הבטחת זמינות בין שרתים.

## הכנה

1. הגדירו DNS לשרת, פתחו כניסה ל־80 ו־443 בלבד והקצו שטח דיסק למסמכים ולגיבוי זמני. פורט 80 משמש להפניה ל־HTTPS ולהנפקת תעודה. מסד הנתונים, API ומדדים אינם מפורסמים ישירות.
2. העתיקו `.env.example` אל `.env` והריצו `chmod 600 .env`. הגדירו סיסמה אקראית למסד (`openssl rand -hex 32`), דומיין וכתובת ופרטי אימות למתאם הזהות. הסיסמה צריכה להתאים לשימוש ב־URL.
3. חברו starter להזדהות: הוא צריך לספק session אמיתי ב־cookie מוגן ומתאם introspection בצד השרת. `OCR_IDENTITY_URL` ו־`OCR_IDENTITY_SECRET` אינם תחליף לשירות זהות. בלי החיבור אין כניסה פעילה; המערכת אינה מקבלת תפקיד או זהות מהדפדפן כמקור מוסמך. הגדירו לפי הצורך `OCR_LOGIN_URL` ו־`OCR_MEMBERS_URL` למסכי הכניסה וניהול החברים.
4. צרו `secrets/alertmanager.yml` מתוך `docker/alertmanager.example.yml`, החליפו את כתובת ה־webhook ביעד התפעולי, והגבילו גישה לקובץ. אין לשמור אותו ב־Git. ודאו שהמשתמש בתמונת Alertmanager יכול לקרוא אותו.
5. הריצו `docker compose config --quiet`, לאחר מכן `docker compose up -d --build`. שירות המיגרציה חייב להסתיים בהצלחה לפני עליית ה־API והעובדים. אין להריץ `down -v` על סביבת ייצור.

הנתונים נמצאים ב־volumes קבועים. מסד הגרסה החדשה משתמש ב־`enterprise_postgres_data` כדי שלא לנסות לפתוח volume ישן של PostgreSQL 15 באמצעות PostgreSQL 16. נתוני התקנה ישנה אינם מועברים אוטומטית; העברה דורשת גיבוי ושחזור מתוכנן ובדיקת התאימות, ללא מחיקת ה־volume הישן. תהליכי Python רצים כמשתמש 10001, ותיקיית המסמכים פרטית. לכל עובד מגבלת 4GB זיכרון, שני מעבדים ו־256 תהליכים; התאימו לחומרה לאחר מדידה. התור מגביל כברירת מחדל שני מסמכים בכל המערכת ואחד לצוות. לשינוי מספר העובדים אפשר להשתמש ב־`docker compose up -d --scale worker=2`.

בדיקת מוכנות פנימית: `docker compose exec api curl -fsS http://localhost:8000/health/ready`. ממשק המדדים הוא `/metrics` בתוך רשת Docker בלבד. Caddy חוסם גישה ציבורית לבריאות ולמדדים. גישה ציבורית ל־`/api/v1/*` מיועדת לאינטגרציות מאומתות.

## גיבוי ושחזור

על שרת Linux התקינו `restic` ו־`flock`. הגדירו יעד **מחוץ לשרת**, קובץ סיסמת הצפנה והרשאות גישה ליעד. שמרו עותק מוגן ונפרד של סיסמת restic; בלעדיה אין שחזור. אתחול ראשון מתבצע באמצעות `restic init` עם משתני `RESTIC_*` המתאימים.

`scripts/backup.sh` עוצר זמנית את השירותים הכותבים, שומר dump ואת כל המסמכים יחד, מצפין ושולח ל־restic, ומחזיר את השירותים. יש חלון תחזוקה בזמן הגיבוי; הוא נחוץ לעקביות בין הקבצים למסד. הקבצים הזמניים מקבלים הרשאות פרטיות ונמחקים בסיום. ודאו מקום פנוי להעתק המסמכים. הסקריפט שומר גיבויים משבעת הימים האחרונים ומבצע בדיקת repository. הריצו פעם ביום באמצעות systemd timer או cron שמטעין את קובץ הסודות הפרטי. אל תכניסו סיסמאות ישירות לשורת cron.

הסקריפט מפרסם תוצאת גיבוי וזמן הצלחה ל־`backup-staging/metrics/backup.prom`. Prometheus ו־Alertmanager מתריעים על כישלון או איחור מעל 25 שעות, API שאינו מגיב, תור תקוע, heartbeat ישן ודיסק מתמלא. לפני כניסה לייצור בדקו קבלת התראה ביעד האמיתי. בדיקת repository אינה מחליפה תרגיל שחזור.

לתרגיל שחזור השתמשו בשרת בדיקה או בפרויקט Compose נפרד **ללא containers או volumes קיימים**:

```bash
export COMPOSE_PROJECT_NAME=ocr-restore-rehearsal
export OCR_RESTORE_CONFIRM=isolated-empty-project
scripts/restore.sh EXPLICIT_SNAPSHOT_ID
```

הסקריפט משחזר מסד וקבצים, מריץ מיגרציות ותחזוקה חד־פעמית למחיקת תוכן שפג תוקפו, ומשאיר את השירות הציבורי כבוי. בדקו ספירת משימות, הרשאות בין צוותים, הורדת מסמך עברי ותוצרת OCR, ואז הפעילו API ועובדים בסביבה המבודדת. יש להגדיר דומיין ופורטים נפרדים לפני הפעלת proxy לצורך התרגיל. אין לבצע שחזור מעל מסד פעיל.

## לפני שימוש ארגוני

- אשרו חיבור starter אמיתי, החלפת צוות והרשאות בעלים, מנהל וחבר; בדקו גם מפתחות API מבוטלים.
- בדקו PDF עברי סרוק, PDF מעורב והורדת PDF וטקסט אחרי סגירת הדפדפן.
- הרגו עובד במהלך משימה ובדקו התאוששות, ביטול וניסיון חוזר בלי תוצר כפול.
- בצעו תרגיל גיבוי ושחזור וקבלת התראות. סודות ויעד גיבוי אמיתיים נדרשים לכך.
- הריצו עומס של 50 משתמשים על מדגם מייצג; תעדו חומרה, גודל קבצים, עמודים, שפות, זמני המתנה ועיבוד. אין להסיק תפוקה יומית מבדיקת API בלבד.

ה־CLI נשאר זמין בתמונה: `docker compose run --rm api python cli/ocr_combined.py --mode cli /app/data/document.pdf`. ממשק GUI דורש סביבת תצוגה מקומית ואינו שירות web.
